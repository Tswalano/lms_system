## PR Summary

This pull request refactors and improves the CI/CD workflow for the employee-management-system repository. Key changes include:

- **Deployment Environment Updates:**  
  - Changed the environment option from `staging` to `dev` for deployment inputs.
  - Adjusted deployment targets and CloudFront distribution IDs to differentiate between `prod` and `dev` environments, ensuring proper separation of production and development deployments.

- **Semantic Release and Versioning:**  
  - Cleaned up the semantic-release step by removing unnecessary debug outputs.
  - Improved the logic for determining the frontend build version:
    - Uses release tag, semantic-release output, latest GitHub release, or package.json as fallback.
    - Appends a `-dev.<SHORT_SHA>` suffix for dev deployments for clearer version identification.
    - Sets the computed version as a workflow output for downstream steps.

- **Frontend Deployment Improvements:**  
  - Refactored S3 sync targets so that production assets go to `prod/` and development assets to `dev-fe/`.
  - CloudFront cache invalidation now uses the correct distribution ID for each environment.

- **Backend Deployment and Destroy:**  
  - Switched context arguments from `env` to `environment` for CDK deploy and destroy commands, improving clarity and consistency.

- **General Workflow Cleanup:**  
  - Removed obsolete or redundant steps, such as an extra git pull and verbose debug statements.
  - Streamlined output passing between steps for better maintainability.

These changes enhance environment handling, version management, and deployment clarity for both frontend and backend components.
